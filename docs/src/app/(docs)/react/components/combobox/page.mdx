## Usage guidelines

- **Combobox is a filterable Select**: Use Combobox when the input is restricted to a set of predefined selectable items, similar to [Select](/react/components/select) but whose items are filterable using an input. Prefer using Combobox over Select when the number of items is sufficiently large to warrant filtering.
- **Avoid for simple search widgets**: Combobox does not allow free-form text input. For search widgets, consider using [Autocomplete](/react/components/autocomplete) instead.
- **Avoid when not rendering an input**: Use [Select](/react/components/select) instead of Combobox if no input is being rendered, which includes accessibility features specific to a listbox without an input.
- **Form controls must have an accessible name**: If `<Combobox.Input>` is the form control, label it with a native `<label>` or `<Field.Label>`, or provide an `aria-label` when no visible label is rendered. `<Combobox.Label>` labels `<Combobox.Trigger>` and is intended for the [input-inside-popup](#input-inside-popup) pattern, where the trigger is the form control. See the [forms guide](/react/handbook/forms).

## Item values

Each `<Combobox.Item>` takes a `value` prop identifying it. Pass the item being rendered:

```jsx title="Using item objects as values"
<Combobox.List>
  {(item) => (
    <Combobox.Item key={item.id} value={item}>
      {item.label}
    </Combobox.Item>
  )}
</Combobox.List>
```

That item is what `value`, `defaultValue`, and `onValueChange` receive. To store IDs instead, see [Value selection with IDs](#value-selection-with-ids).

## Examples

### Typed wrapper component

The following example shows a typed wrapper around the Combobox component with correct type inference and type safety:

```tsx title="Specifying generic type parameters"
import * as React from 'react';
import { Combobox } from '@base-ui/react/combobox';

export function MyCombobox<Value, Multiple extends boolean | undefined = false, Item = Value>(
  props: Combobox.Root.Props<Value, Multiple, Item>,
): React.JSX.Element {
  return <Combobox.Root {...props}>{/* ... */}</Combobox.Root>;
}
```

The third `Item` type parameter is what lets the wrapper accept a `Combobox.createItems()` collection, whose rendered item type differs from its selection value. Omit it and a collection infers `Value` as the source item type, surfacing an error on `defaultValue` rather than on `items`.

### Value selection with IDs

When your app stores IDs rather than item objects, use `Combobox.createItems` with `getValue` and `getLabel` to derive each item's selection value and display label.

With static data, create the collection at module scope. The accessor parameters are inferred from `users`. Pass the derived ID to the `value` prop of `<Combobox.Item>`, not the item being rendered:

```jsx title="Using item IDs as values"
const items = Combobox.createItems(users, {
  getValue: (user) => user.id,
  getLabel: (user) => user.name,
});

<Combobox.Root items={items}>
  <Combobox.List>
    {(user) => (
      <Combobox.Item key={user.id} value={user.id}>
        {user.name}
      </Combobox.Item>
    )}
  </Combobox.List>
</Combobox.Root>;
```

Selection props and events use the derived IDs, while list rendering continues to receive the original items. The derived label is also used for filtering and typeahead.

When the data is loaded or replaced at runtime, memoize the collection on it so that it is rebuilt only when the data changes:

```jsx title="Creating a collection from dynamic data"
const items = React.useMemo(
  () =>
    Combobox.createItems(users, {
      getValue: (user) => user.id,
      getLabel: (user) => user.name,
    }),
  [users],
);
```

import { DemoComboboxCreateItems } from './demos/create-items';

<DemoComboboxCreateItems />

As a rule of thumb, use primitive items for simple lists, object values when the selected record is useful application state, and `createItems()` when selection should use a stable primitive ID while rendering and filtering still use object records.

Stable IDs preserve item matching when an async data library replaces row objects during a refetch. With object values, use `isItemEqualToValue` to compare their IDs instead.

When results are filtered externally (for example, by a server-side search), `items` represents records known to the app, while `filteredItems` represents the current result window displayed in the popup. Pass source items rather than derived values to `filteredItems`, preserving the flat or grouped structure of `items`:

```tsx title="Displaying a window of async results"
const items = React.useMemo(
  () =>
    Combobox.createItems(knownUsers, {
      getValue: (user) => user.id,
      getLabel: (user) => user.name,
    }),
  [knownUsers],
);

<Combobox.Root
  items={items}
  filteredItems={searchResults}
  value={selectedUserId}
  onValueChange={setSelectedUserId}
/>;
```

Include the selected user's record in `knownUsers` so its label remains available when it is outside `searchResults`. Alternatively, provide `itemToStringLabel` when the label can be derived from the selected value alone.

### Multiple select

The combobox can allow multiple selections by adding the `multiple` prop to `<Combobox.Root>`.
Selection chips are rendered with `<Combobox.Chip>` inside the input that can be removed.

import { DemoComboboxMultiple } from './demos/multiple';

<DemoComboboxMultiple />

Visible chips can be limited by slicing the selected values rendered in `<Combobox.Value>`:

```tsx title="Limiting visible chips"
const CHIP_LIMIT = 3;

<Combobox.Value>
  {(selectedValue: string[]) => {
    // @highlight-start
    const visibleValue = selectedValue.slice(0, CHIP_LIMIT);
    const hiddenCount = selectedValue.length - visibleValue.length;
    // @highlight-end
    return (
      <>
        {visibleValue.map((item) => (
          <Combobox.Chip key={item}>
            {item}
            <Combobox.ChipRemove aria-label={`Remove ${item}`} />
          </Combobox.Chip>
        ))}
        {/* @highlight-start */}
        {hiddenCount > 0 && <span>{`+${hiddenCount} more`}</span>}
        {/* @highlight-end */}
        <Combobox.Input />
      </>
    );
  }}
</Combobox.Value>;
```

#### Keeping the filter after selection

In `multiple` mode, selecting an item clears the typed filter and closes the popup when the input is rendered outside it. To let users pick several results from one query, cancel the relevant change request.

Which request to cancel depends on the input's placement. When the input is outside the popup, cancel the `item-press` close request in `onOpenChange`. When it is inside, cancel the clear request in `onInputValueChange`, marked with `eventDetails.isItemPress`.

```jsx title="Input outside the popup"
<Combobox.Root
  multiple
  onOpenChange={(open, eventDetails) => {
    if (!open && eventDetails.reason === 'item-press') {
      eventDetails.cancel();
    }
  }}
>
  {/* ... */}
</Combobox.Root>
```

```jsx title="Input inside the popup"
<Combobox.Root
  multiple
  onInputValueChange={(value, eventDetails) => {
    if (eventDetails.isItemPress) {
      eventDetails.cancel();
    }
  }}
>
  {/* ... */}
</Combobox.Root>
```

The typed filter still resets once the popup closes.

### Grouped

Organize related options with `<Combobox.Group>` and `<Combobox.GroupLabel>` to add section headings inside the popup.

Groups are represented by an array of objects with an `items` property, which itself is an array of individual items for each group. An extra property, such as `value`, can be provided for the heading text when rendering the group label.

```tsx title="Example"
interface ProduceGroupItem {
  value: string;
  // @highlight
  items: string[];
}

const groups: ProduceGroupItem[] = [
  {
    value: 'Fruits',
    // @highlight
    items: ['Apple', 'Banana', 'Orange'],
  },
  {
    value: 'Vegetables',
    // @highlight
    items: ['Carrot', 'Lettuce', 'Spinach'],
  },
];
```

### Virtualized

For most large datasets, use the [`<Virtualizer>`](/react/utils/virtualizer) component. It is the recommended approach because it renders only the visible items while handling Combobox keyboard navigation, scrolling, selection, and accessibility metadata for you.

Pass a flat collection to the `items` prop on `<Combobox.Root>`, and use the virtualizer as the only item-rendering child of `<Combobox.List>`. Each item renderer must return exactly one `<Combobox.Item>`. Grouped collections and grid mode are not currently supported.

```jsx title="Anatomy"
import { Virtualizer } from '@base-ui/react/virtualizer';

// prettier-ignore
<Combobox.List>
  <Virtualizer getItemKey={(item) => item.id}>
    {(item) => <Combobox.Item value={item}>{item.name}</Combobox.Item>}
  </Virtualizer>
</Combobox.List>
```

The virtualizer is the scroll container, so constrain its height or maximum height. The `--total-size` CSS variable contains the estimated or measured height of the virtual content, including the virtualizer's own block padding, and can be combined with `--available-height` from `<Combobox.Positioner>`:

```css
.Scroller {
  box-sizing: border-box;
  height: min(22.5rem, var(--total-size));
  max-height: var(--available-height);
  overflow: auto;
  padding-block: 0.25rem;
}
```

Padding on the virtualizer behaves as it does on a plain scrolling list: items start below it, scroll through it, and end above it.

Sizing depends on what constrains the scroll container. Inside a popup, which is sized by its content, `height` must come from `--total-size` as above: without it the container would size itself from the items it happened to render, which changes how many it renders, and the two chase each other. Where the height is already definite — a panel in a page layout, say — that is not needed, and `max-height` alone is enough.

Use `getItemKey` to provide stable identity when item values are objects or when TypeScript cannot infer the item type. For primitive values, you can instead declare the type explicitly, such as `<Virtualizer<string>>`. `estimatedItemHeight` defaults to 32 pixels and adapts to measured items. It can also be a number or a function receiving the item and its filtered index. `overscanPx` controls the extra pixel buffer around the visible range. It defaults to the larger of 150px and the first item's estimated height; even an explicit value of `0` keeps a minimum render buffer of one estimated row. CSS `scroll-padding-top` and `scroll-padding-bottom` are respected when keyboard navigation scrolls an item into view.

The scroll container the virtualizer renders is deliberately not a tab stop. Focus stays in the input for the whole interaction, as the combobox pattern requires, and the list is driven by `aria-activedescendant`: arrow keys move the highlight one item at a time, <kbd>Page&nbsp;Down</kbd> and <kbd>Page&nbsp;Up</kbd> move it ten at a time, and the list scrolls to follow it. Every item is reachable that way, including items that have never been rendered, which is why <kbd>Tab</kbd> is left to dismiss the popup rather than to enter the list.

Automated accessibility checks flag any scrollable region that cannot be focused, so this container is reported by rules such as axe's `scrollable-region-focusable`. Making it focusable would satisfy the check and break the pattern: <kbd>Tab</kbd> would move into the list instead of dismissing it, and a keyboard user would be left inside a scroll container with no way to choose an item. Suppress the finding for this element.

Content that is not an item — a loading indicator, an end-of-results note — goes in `trailing`. It renders after the last item inside the scroll container, scrolls with the items, and is measured into the scrollable height, rather than being pinned below the list where it would sit still while the list moves. It takes no index and is left out of `aria-setsize` and `aria-posinset`.

A list may only contain options, so `trailing` content must not present itself as one. Keep it out of the accessibility tree and convey what it stands for another way — `aria-busy` on the list while a page is loading, with a live region outside it to announce the result:

```jsx title="A loading row"
<Virtualizer trailing={loading ? <Spinner aria-hidden="true" /> : null} onEndReached={loadNextPage}>
  {(item) => <Combobox.Item value={item}>{item.name}</Combobox.Item>}
</Virtualizer>
```

Interactive affordances are a different case: a control inside the list would be neither valid there nor reachable, since focus stays in the input. Keep buttons such as a create-new action outside the list, where they are in the tab order.

When some items are disabled, pass `isItemDisabled` to `<Combobox.Root>`. Its index argument is the item's index in the filtered and limited collection. The `disabled` prop only marks a rendered `<Combobox.Item>` as disabled; `isItemDisabled` is the predicate keyboard navigation uses, including while an item is outside the rendered window.

#### Third-party virtualizers

You can instead integrate a third-party virtualization library when your application already uses one or needs behavior that the built-in virtualizer does not provide. `<Virtualizer>` is recommended for most cases because a third-party integration must coordinate filtering, item indexes, scrolling, and accessibility metadata itself.

Set the `virtualized` prop on `<Combobox.Root>` only for an external virtualizer. Read the current filtered collection with `useFilteredItems()`, render the virtual rows as `<Combobox.Item>` elements, and pass each item its index in the filtered collection. The following example integrates [`@tanstack/react-virtual`](https://tanstack.com/virtual/latest):

#### Memoizing items

Memoizing each item is a simpler alternative to virtualization for datasets up to roughly 1,000 items. Wrap each item in [`React.memo`](https://react.dev/reference/react/memo) and pass the item as a prop so unchanged items skip re-rendering. While memoization speeds up typing, it does not speed up opening; with a large enough number of items, the mount cost dominates, and virtualization becomes necessary to keep the open interaction fast on low-end devices.

```tsx title="Memoizing list items"
interface Fruit {
  id: string;
  label: string;
}

const FruitItem = React.memo(function FruitItem({ item }: { item: Fruit }) {
  return (
    <Combobox.Item value={item}>
      <Combobox.ItemIndicator />
      <span>{item.label}</span>
    </Combobox.Item>
  );
});

<Combobox.List>{(item: Fruit) => <FruitItem key={item.id} item={item} />}</Combobox.List>;
```
