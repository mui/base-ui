## Usage guidelines

- **Use for searchable actions**: Choose `FilterMenu` when users need to find an action. Use [Menu](/react/components/menu) for a short list that does not need search.
- **Use Combobox for values**: Choose [Combobox](/react/components/combobox) when users are selecting a value rather than running an action.
- **Name the filter input**: Give `<FilterMenu.Input>` an accessible name with `aria-label`, `aria-labelledby`, or a visible native `<label>`.

## Anatomy

Import the component and assemble its parts:

```jsx title="Anatomy"
import { FilterMenu } from '@base-ui/react/filter-menu';

<FilterMenu.Root>
  <FilterMenu.Trigger>Actions</FilterMenu.Trigger>
  <FilterMenu.Portal>
    <FilterMenu.Backdrop />
    <FilterMenu.Positioner>
      <FilterMenu.Popup>
        <FilterMenu.Input aria-label="Filter actions" />
        <FilterMenu.Clear aria-label="Clear filter" />
        <FilterMenu.Empty>No actions found.</FilterMenu.Empty>
        <FilterMenu.List>
          <FilterMenu.Item>Edit</FilterMenu.Item>
          <FilterMenu.Item>Duplicate</FilterMenu.Item>
        </FilterMenu.List>
      </FilterMenu.Popup>
    </FilterMenu.Positioner>
  </FilterMenu.Portal>
</FilterMenu.Root>;
```

`FilterMenu` supports checkbox items, radio groups, links, groups, and submenus like [Menu](/react/components/menu).

## Accessibility

The popup uses `dialog` semantics and the item list uses `menu` semantics. Real focus stays on the search field while the highlighted item is exposed through `aria-activedescendant`.

Typing filters the items, Arrow keys move the highlight, and <kbd>Enter</kbd> activates the highlighted action. Give the input an accessible name so screen reader users can identify the filter.

### Filtering items

Items match their rendered text by default. Use `label` to provide explicit searchable text and `keywords` for alternate terms.

```jsx title="Labels and keywords"
<FilterMenu.List>
  <FilterMenu.Item label="Rename" keywords={['edit name']}>
    Rename
  </FilterMenu.Item>
  <FilterMenu.Item label="Move to folder" keywords={['organize']}>
    Move
  </FilterMenu.Item>
</FilterMenu.List>
```

Groups with no matching items are hidden, including their labels. `FilterMenu.Empty` is shown when no items match.

### Custom matching

Use `filter` to replace the default case-insensitive substring matching:

```jsx title="Custom filter"
<FilterMenu.Root filter={(itemText, query) => itemText.startsWith(query)}>
  {/* menu parts */}
</FilterMenu.Root>
```

When supplied, the custom filter replaces keyword matching.

### Filterable submenus

Use `<FilterMenu.SubmenuRoot>` when a submenu needs its own search input.

```jsx title="A filterable submenu"
<FilterMenu.SubmenuRoot>
  <FilterMenu.SubmenuTrigger>More actions</FilterMenu.SubmenuTrigger>
  <FilterMenu.Portal>
    <FilterMenu.Positioner>
      <FilterMenu.Popup>
        <FilterMenu.Input aria-label="Filter more actions" />
        <FilterMenu.List>
          <FilterMenu.Item>Share</FilterMenu.Item>
          <FilterMenu.Item>Move</FilterMenu.Item>
        </FilterMenu.List>
      </FilterMenu.Popup>
    </FilterMenu.Positioner>
  </FilterMenu.Portal>
</FilterMenu.SubmenuRoot>
```
