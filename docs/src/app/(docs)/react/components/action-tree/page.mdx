## Usage guidelines

- **Avoid when items hold no controls**: Use [Tree](/react/components/tree) instead when each item is a single element, including items that toggle like a checkbox or link to another page. Screen readers read a tree item as a whole, and users need fewer key presses. Action Tree follows the [treegrid pattern](https://www.w3.org/WAI/ARIA/apg/patterns/treegrid/) with one cell per item, so keyboard users can reach the buttons, inputs, and links inside each item.
- **Give the tree an accessible name**: Prefer `<ActionTree.Label>`, or provide an `aria-label` on `<ActionTree.List>` when no visible label is rendered.
- **Name every control**: Give each control inside an item a name that includes the item's label, such as "Remove Wireframes". The checkbox, expansion trigger, and clear button have English names, such as "Select Documents", "Expand Documents", and "Clear filter": pass your own `aria-label` to translate them.
- **Support touch screen readers**: VoiceOver on iOS and TalkBack users can't press arrow keys. Render `<ActionTree.ItemExpansionTrigger>`, and `<ActionTree.ItemCheckbox>` with checkbox selection, so they can expand and select items by tapping.

## Anatomy

Import the component and assemble its parts:

```jsx title="Anatomy"
import { ActionTree } from '@base-ui/react/action-tree';

<ActionTree.FilterProvider>
  <ActionTree.Root>
    <ActionTree.Label />
    <ActionTree.Input />
    <ActionTree.Clear />
    <ActionTree.Status />
    <ActionTree.Empty />

    <ActionTree.List>
      {(item) => (
        <>
          <ActionTree.Item itemId={item.id}>
            <ActionTree.ItemContent>
              <ActionTree.ItemIndentGuide />
              <ActionTree.ItemExpansionTrigger />
              <ActionTree.ItemCheckbox>
                <ActionTree.ItemCheckboxIndicator />
              </ActionTree.ItemCheckbox>
              <ActionTree.ItemGroupIndicator />
              <ActionTree.ItemLink />
              <ActionTree.ItemInput />
              <ActionTree.ItemButton />
              <ActionTree.ItemControl />
            </ActionTree.ItemContent>
          </ActionTree.Item>
          <ActionTree.GroupTransition />
        </>
      )}
    </ActionTree.List>
  </ActionTree.Root>
</ActionTree.FilterProvider>;
```

Action Tree shares the rest of its API with [Tree](/react/components/tree). Item models, selection, expansion, animation, filtering, status messages, and updates work the same way, with `ActionTree` parts in place of `Tree` parts. The cell and its controls only work in `<ActionTree.Root>`, and `<Tree.CheckboxItem>` and `<Tree.LinkItem>` only in `<Tree.Root>`: each throws in the other root.

## Controls inside items

Each item is a row with a single cell, `<ActionTree.ItemContent>`. Render the content of the item inside it, and its controls with `<ActionTree.ItemButton>`, `<ActionTree.ItemInput>`, `<ActionTree.ItemLink>`, `<ActionTree.ItemCheckbox>`, or `<ActionTree.ItemControl>`.

```tsx title="Controls inside an item"
<ActionTree.Root items={tasks}>
  <ActionTree.List>
    {(task) => (
      <ActionTree.Item itemId={task.id} aria-description="Press Tab to reach the task controls">
        <ActionTree.ItemContent>
          <ActionTree.ItemLink href={task.url}>{task.label}</ActionTree.ItemLink>
          <ActionTree.ItemInput aria-label={`Estimate for ${task.label}`} />
          <ActionTree.ItemButton aria-label={`Remove ${task.label}`}>
            <RemoveIcon />
          </ActionTree.ItemButton>
        </ActionTree.ItemContent>
      </ActionTree.Item>
    )}
  </ActionTree.List>
</ActionTree.Root>
```

As in a tree, <kbd>Arrow Up</kbd> and <kbd>Arrow Down</kbd> move between items. <kbd>Arrow Right</kbd> and <kbd>Tab</kbd> move from an item to its controls, and on a collapsed item, <kbd>Arrow Right</kbd> expands it first. Between controls, <kbd>Arrow Left</kbd> and <kbd>Arrow Right</kbd> move to the previous or next control. <kbd>Arrow Left</kbd> on the first control, or <kbd>Escape</kbd> on any control, returns to the item.

A focused item announces its label, not its controls or the rest of its content.

- Describe how to reach the controls with `aria-description` on the items that have them, or once on `<ActionTree.List>` when most items do.
- Pass secondary content, such as a count or a status, to `aria-describedby` on `<ActionTree.Item>`.

Base UI doesn't ship these strings, so translate them with the rest of your interface.

To use a popup trigger as a control, pass it to the `render` prop of `<ActionTree.ItemButton>`:

```tsx title="Using popups with item controls"
<Menu.Root>
  {/* @highlight */}
  <ActionTree.ItemButton render={<Menu.Trigger />} aria-label={`Actions for ${item.label}`} />
  <Menu.Portal>{/* Compose the rest of the menu */}</Menu.Portal>
</Menu.Root>
```

Controls keep the keys they use, such as the caret keys of a text input or the up and down arrows of a popup trigger. Typeahead characters, <kbd>Space</kbd>, and <kbd>Enter</kbd> always belong to the control. Use the `controlKeys` prop to change which keys a control keeps. `<ActionTree.ItemControl>` keeps every key by default, so assign the key groups the tree should handle. For example, a custom rating widget that only uses the left and right arrows:

```tsx title="Custom control"
<ActionTree.ItemControl
  render={<RatingInput />}
  controlKeys={{ vertical: 'tree', homeEnd: 'tree', escape: 'tree' }}
/>
```

The part must render the element that receives focus. Other focusable elements inside an item keep all of their keys, stay out of the item's navigation, and add a tab stop to every item.

## Examples

### Checkbox selection

Render `<ActionTree.ItemCheckbox>` inside `<ActionTree.ItemContent>` to select an item with a checkbox, and `<ActionTree.ItemCheckboxIndicator>` inside it to show the state. Set `selectionMode="multiple"` on `<ActionTree.Root>` to allow more than one item to be selected.

A click on the checkbox toggles its item and keeps the other items selected, while a click elsewhere on the item selects only that item. [Selection propagation](/react/components/tree#selection-propagation) works as in Tree.

import { DemoActionTreeCheckboxSelection } from './demos/checkbox-selection';

<DemoActionTreeCheckboxSelection />

### Links

Render `<ActionTree.ItemLink>` inside `<ActionTree.ItemContent>` to link an item to another page, and set `active` on the current page's link. It marks the link and its item with `aria-current="page"`. Tabbing into the tree focuses the current page's item, unless an item is selected or another item had focus before. With `selectionMode="none"`, <kbd>Enter</kbd> on an item follows its first link.

When a link is the only control of an item, use [`<Tree.LinkItem>`](/react/components/tree#links) instead.

import { DemoActionTreeLinks } from './demos/links';

<DemoActionTreeLinks />

### Filtering

Wrap `<ActionTree.Root>` in `<ActionTree.FilterProvider>` and add `<ActionTree.Input>` inside the root. Typing while an item has focus continues the query, but typing in a control doesn't. See [filtering in Tree](/react/components/tree#filtering) for matching and display modes.

## createItems

Normalizes a custom item model into a collection for the `items` prop of `<ActionTree.Root>`, deriving each item's ID, label, and children.
Create static collections at module scope, and memoize dynamic collections by their data and every value their accessors read.

<TypesActionTree.createItems hideDescription />

## useFilter

Matches items against a query using `Intl.Collator` for robust string matching.
This hook is used when customizing how items match.
Call its methods inside the `filter` prop of `<ActionTree.FilterProvider>`.
