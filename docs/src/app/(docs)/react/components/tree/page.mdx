## Usage guidelines

- **Avoid when items contain controls**: A tree item is one focusable element that screen readers read as a whole, so it can't hold buttons, inputs, or links that keyboard users need to reach. Use [Tree Grid](/react/components/tree-grid) for those items instead.
- **Avoid trees for site navigation**: Prefer links grouped under disclosure buttons, such as [Collapsible](/react/components/collapsible). The [WAI-ARIA Authoring Practices](https://www.w3.org/WAI/ARIA/apg/patterns/treeview/examples/treeview-navigation/) caution against trees for site navigation. If you use one, follow the [links](#links) example.
- **Give the tree an accessible name**: Prefer `<Tree.Label>`, or provide an `aria-label` on `<Tree.List>` when no visible label is rendered.
- **Name every control**: Give `<Tree.Input>` a visible `<label>`, since a placeholder disappears once the user types. An item is named by its `label`, so pass other visible content, such as a size, to `aria-describedby`. The expansion trigger and the clear button have English names, such as "Expand Documents" and "Clear filter": pass your own `aria-label` to translate them, based on `state.expanded` for the trigger.
- **Support touch screen readers**: VoiceOver on iOS and TalkBack users can't press arrow keys. Render `<Tree.ItemExpansionTrigger>` so they can expand items by tapping. It's the only reliable way in a right-to-left tree, where TalkBack's Expand and Collapse actions are reversed on the item that has focus. With `multiple="opt-in"`, render `<Tree.CheckboxItem>` so that tapping an item toggles it without clearing the others.

## Anatomy

Import the component and assemble its parts:

```jsx title="Anatomy"
import { Tree } from '@base-ui/react/tree';

<Tree.FilterProvider>
  <Tree.Root>
    <Tree.Label />
    <Tree.Input />
    <Tree.Clear />
    <Tree.Status />
    <Tree.Empty />

    <Tree.List>
      {(item) => (
        <>
          <Tree.Item itemId={item.id}>
            <Tree.ItemIndentGuide />
            <Tree.ItemExpansionTrigger />
            <Tree.ItemGroupIndicator />
          </Tree.Item>
          <Tree.GroupTransition />
        </>
      )}
    </Tree.List>
  </Tree.Root>
</Tree.FilterProvider>;
```

`<Tree.CheckboxItem>` and `<Tree.LinkItem>` replace `<Tree.Item>` for items that toggle like a checkbox or link to another page. They take the same children, and `<Tree.CheckboxItemIndicator>` goes inside `<Tree.CheckboxItem>`.

`<Tree.FilterProvider>` wraps `<Tree.Root>` to add filtering, so trees without it don't bundle the filter. Adding or removing it remounts the tree, so keep it rendered and pass an empty `value` to turn filtering off.

## Item models

To add fields to the standard item, extend `Tree.DefaultItem` and redeclare `children` with your own type. Otherwise, nested items only need the standard fields, while callbacks type them as your model.

```tsx title="Extending the standard item"
interface Folder extends Tree.DefaultItem {
  color: string;
  children?: Folder[];
}
```

For any other item model, use `Tree.createItems()`. Supply `setChildren` for nested edits and managed reparenting.

```tsx title="Custom item model"
const items = Tree.createItems(nodes, {
  getId: (node) => node.key,
  getLabel: (node) => node.name,
  getChildren: (node) => node.nodes,
  setChildren: (node, children) => ({ ...node, nodes: [...children] }),
});

<Tree.Root items={items}>
  <Tree.List<Node>>{(node) => <Row node={node} />}</Tree.List>
</Tree.Root>;
```

The root infers the item type from `items`. Parts outside the root's props, such as `<Tree.List>` and the providers, can't see it, so they type items as `any` unless you pass the type, as `<Tree.List<Node>>` does.

## Examples

### Multiple selection

Set `multiple` on `<Tree.Root>` to let users select more than one item. A click or <kbd>Space</kbd> adds or removes an item, as does <kbd>Enter</kbd> on an item that can't expand, and the selected items are an array.

### Opt-in multiple selection

Use `multiple="opt-in"` when users opt in to selecting more than one item by holding a modifier key. Without one, a click or moving focus with the keyboard moves the selection to a single item.

- <kbd>Ctrl</kbd> or <kbd>Cmd</kbd>+click adds or removes an item.
- <kbd>Shift</kbd>+click selects a range, as does <kbd>Shift</kbd>+<kbd>Arrow Up</kbd> or
  <kbd>Arrow Down</kbd>.
- <kbd>Ctrl</kbd>+<kbd>Arrow Up</kbd> or <kbd>Arrow Down</kbd> moves focus without changing the
  selection, and <kbd>Ctrl</kbd>+<kbd>Space</kbd> adds or removes the focused item. On macOS, use
  <kbd>Option</kbd> instead of <kbd>Ctrl</kbd>.

On touch devices, which have no modifier keys, a tap adds or removes an item, the same as `multiple`. A `<Tree.CheckboxItem>` always selects as with `multiple`.

### Checkbox selection

Render `<Tree.CheckboxItem>` in place of `<Tree.Item>` to select items like checkboxes, and `<Tree.CheckboxItemIndicator>` inside it to show the state. Set `multiple` on `<Tree.Root>` to allow more than one item to be selected. In single selection, checking an item unchecks the others, so use `<Tree.Item>` there instead.

import { DemoTreeCheckboxItems } from './demos/checkbox-items';

<DemoTreeCheckboxItems />

### Selection propagation

The `checkboxSelectionPropagation` prop controls how checking an item affects related items, with a `<Tree.CheckboxItem>` or with `actionsRef.setItemSelection()`. With `descendants`, checking a parent selects its whole branch. With `parents`, checking all of its selectable children selects the parent. Both are enabled by default with multiple selection. Pressing a `<Tree.Item>` selects or deselects that item only.

import { DemoTreeSelectionPropagation } from './demos/selection-propagation';

<DemoTreeSelectionPropagation />

### Select all

With multiple selection, <kbd>Ctrl</kbd>+<kbd>A</kbd> or <kbd>Cmd</kbd>+<kbd>A</kbd> selects every item, including the ones under collapsed parents, and `onSelectedItemsChange` receives their IDs in tree order. Disabled items keep their state: a selected one stays selected, and the others stay unselected. While the tree is filtered, the shortcut adds the items the filter shows to the selection and keeps the rest of it.

### Rendering items

To render the items, pass a function to `Tree.List`. It's called with each item in view:

```jsx title="Rendering items with a function"
<Tree.Root items={items}>
  <Tree.List>
    {(item) => (
      <Tree.Item itemId={item.id}>
        <Tree.ItemExpansionTrigger />
        {item.label}
      </Tree.Item>
    )}
  </Tree.List>
</Tree.Root>
```

A function can't be passed from a Server Component, so a tree rendered this way must be in a Client Component. You can also map over the data yourself and render an item part for each item as children, which works in either:

```jsx title="Rendering items as children"
function TreeItems({ items }) {
  return items.map((item) => (
    <React.Fragment key={item.id}>
      <Tree.Item itemId={item.id}>
        <Tree.ItemExpansionTrigger />
        {item.label}
      </Tree.Item>
      {item.children && <TreeItems items={item.children} />}
    </React.Fragment>
  ));
}

<Tree.Root items={items}>
  <Tree.List>
    <TreeItems items={items} />
  </Tree.List>
</Tree.Root>;
```

An item part rendered as a child renders nothing while one of its ancestors is collapsed or the filter hides it. When you render the items this way:

- **Render every item, in order**: Render an item part for each item in `items`, collapsed ones included, with its children right after it. Keyboard navigation can't reach an item that isn't rendered.
- **Make the item part the outer element**: Only the item part hides, so content around it stays visible. Use its `render` prop to change the element instead.
- **Render the data you pass to `items`**: With `defaultItems`, the items that [`actionsRef`](#updating-items) adds aren't in your data, so they don't render. Pass `items` and update it in `onItemsChange` instead.
- **Prefer a function for large or animated trees**: A function renders only the items in view, and only a function can animate branches with `<Tree.GroupTransition>`.

Tree doesn't virtualize its rows yet. It renders a row for every item whose ancestors are expanded, including rows scrolled out of view, and keyboard navigation can't move focus to a row that isn't rendered.

### Filtering

Wrap `<Tree.Root>` in `<Tree.FilterProvider>` and add `<Tree.Input>` inside the root.

import { DemoTreeFiltering } from './demos/filtering';

<DemoTreeFiltering />

A match keeps its ancestors visible. Use `mode` to choose how the items that don't match are shown.
Changes that replace the selection, such as a press, a <kbd>Shift</kbd> range, or <kbd>Ctrl</kbd>+<kbd>A</kbd>, keep the selected items that the filter hides.

#### Matching items

Items match their label by default and receive a `data-filter-match` attribute. Screen readers don't announce it, so describe matches with `aria-description`, as the demo does.

By default, an item matches when its label contains the query, ignoring case, accents, and punctuation.
Use `filter` to replace the matching. It receives each item's label, the trimmed query, and the item, and keeps the item when it returns `true`.

```jsx title="Custom matching"
<Tree.FilterProvider
  filter={(text, query, item) => text.startsWith(query) || item.tags.includes(query)}
>
  <Tree.Root items={items}>{/* tree parts */}</Tree.Root>
</Tree.FilterProvider>
```

`Tree.useFilter` provides the same locale-aware comparisons:

```jsx title="Locale-aware prefix matching"
const { startsWith } = Tree.useFilter();

<Tree.FilterProvider filter={startsWith}>
  <Tree.Root items={items}>{/* tree parts */}</Tree.Root>
</Tree.FilterProvider>;
```

#### External filtering

To match items on a server, pass the matches to `filteredItems`. The tree keeps showing their ancestors and applies `mode`. Every match must also be in the tree's items.

```jsx title="Server-side matches"
<Tree.FilterProvider value={query} onValueChange={setQuery} filteredItems={matches}>
  <Tree.Root items={items}>{/* tree parts */}</Tree.Root>
</Tree.FilterProvider>
```

To render the results yourself, pass `filter={null}` and give the root the filtered items. Selected items you leave out stay selected when a press toggles another item, and a press that replaces the selection or <kbd>Ctrl</kbd>+<kbd>A</kbd> drops them.

### Status messages

`<Tree.Status>` politely announces the number of filter matches and of selected items to screen readers.
Keep it mounted and hide it visually, as the demos above do, since screen readers don't reliably announce a live region that appears with its message.

The messages are in English.
To translate them or write your own, pass the content as `children`, or a function that receives the latest `change` and its default `message`:

```jsx title="Custom status messages"
<Tree.Status>
  {({ change, message }) =>
    change?.type === 'filter' ? `${change.matchCount} files found.` : message
  }
</Tree.Status>
```

### Sticky ancestors

To keep the ancestors of the rows at the top visible while scrolling, render copies of them above the list. With a fixed row height, the scroll position tells which row each copy covers, and `actionsRef` gives that row's ancestors. Hide the copies from assistive technology, and in `onItemHighlighted`, scroll a highlighted row out from under them.

### Updating items

Use `actionsRef.current.applyTransaction()` to add, update, move, or remove items without rebuilding `items` yourself. The operations apply in the order they're called, as a single change, and each one sees the items as the earlier ones left them.

import { DemoTreeUpdatingItems } from './demos/updating-items';

<DemoTreeUpdatingItems />

`onItemsChange` lists the changes in `eventDetails.changes`, in the order they applied, so applying them to another copy of the items, such as on a server, gives the same result. With a controlled `items`, inserted items render only once the parent passes them back, so wait for that before focusing them.

## Keyboard interactions

In every selection mode:

- <kbd>Arrow Down</kbd> and <kbd>Arrow Up</kbd> move focus to the next and previous rows. Focus
  stops at the first and last rows.
- <kbd>Arrow Right</kbd> expands a collapsed row, and moves focus to the first child of an expanded
  one.
- <kbd>Arrow Left</kbd> collapses an expanded row, and moves focus to the parent of any other row.
- <kbd>Home</kbd> and <kbd>End</kbd> move focus to the first and last rows.
- <kbd>Page Up</kbd> and <kbd>Page Down</kbd> move focus by as many rows as fit in the scroll
  container.
- <kbd>\*</kbd> expands every sibling of the focused row.
- Typing characters moves focus to the next row whose label starts with them, ignoring case. A space typed during the search is part of it, so "New folder" can match. The search ends after a pause, or when focus leaves the tree. With a `<Tree.Input>`, the characters go to the input instead.
- <kbd>Space</kbd> selects the focused row.
- <kbd>Enter</kbd> expands or collapses a row that can expand, and selects any other row. It follows the link of a `<Tree.LinkItem>` and selects the row.
- <kbd>Tab</kbd> moves focus into the tree and out of it. Focus returns to the row that had it last,
  or else to the first selected row, the row that links to the current page, or the first row.

With `multiple`, each row toggles on its own:

- <kbd>Space</kbd> adds or removes the focused row, as does <kbd>Enter</kbd> on a row that can't
  expand.

With `multiple="opt-in"`, the selection follows focus:

- Arrow keys, <kbd>Home</kbd>, <kbd>End</kbd>, <kbd>Page Up</kbd>, <kbd>Page Down</kbd> and typing move the selection to the row they move focus to. On a disabled row or a `<Tree.CheckboxItem>`, the selection stays where it was.
- <kbd>Space</kbd> makes the focused row the only selected row, as does <kbd>Enter</kbd> on a row
  that can't expand.
- See [Opt-in multiple selection](#opt-in-multiple-selection) for the keys that move focus without the selection, and that add or remove single rows.

In both multiple modes:

- <kbd>Shift</kbd>+<kbd>Arrow Down</kbd> or <kbd>Arrow Up</kbd> moves focus, and replaces the
  selection with the rows from the focused row to the one it moves to. Right after a press with
  <kbd>Shift</kbd> or another <kbd>Shift</kbd>+arrow key, it grows or shrinks that range instead.
- <kbd>Shift</kbd>+<kbd>Space</kbd> replaces the selection with the range from the anchor to the
  focused row. The anchor is the row that was last pressed without <kbd>Shift</kbd>, or the start of
  the last range. With `multiple="opt-in"`, moving the selection with the keyboard moves the anchor
  too. When there's no anchor, or it's under a collapsed parent, the range starts at the first
  selected row, or at the first row.
- <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>Home</kbd> or <kbd>End</kbd> adds the rows from the focused
  row to the first or last row to the selection. On macOS, use <kbd>Cmd</kbd> instead of
  <kbd>Ctrl</kbd>.
- <kbd>Ctrl</kbd> or <kbd>Cmd</kbd>+<kbd>A</kbd> selects every item, as [Select all](#select-all)
  describes.

<kbd>Space</kbd> checks or unchecks a `<Tree.CheckboxItem>`, as does <kbd>Enter</kbd> when it can't expand. With `multiple="opt-in"`, it behaves as with `multiple`.

None of these keys expand, collapse, or select a disabled row. It still takes focus unless `itemFocusableWhenDisabled` is `false`, ranges and <kbd>Ctrl</kbd>+<kbd>A</kbd> skip it, and a selected one stays selected. A disabled tree leaves the tab order.

In `<Tree.Input>`:

- <kbd>Arrow Down</kbd> and <kbd>Arrow Up</kbd> move focus to the first and last matches. While the
  tree isn't filtered, they move it to the row <kbd>Tab</kbd> would reach.
- <kbd>Enter</kbd> moves focus to the first match.
- <kbd>Esc</kbd> clears the query.

In right-to-left layouts, <kbd>Arrow Right</kbd> and <kbd>Arrow Left</kbd> swap. The tree doesn't handle <kbd>Esc</kbd> on a row, so a popup or dialog around it can close.

## useFilter

Matches items against a query using `Intl.Collator` for robust string matching.
This hook is used when customizing how items match.
Call its methods inside the `filter` prop of `<Tree.FilterProvider>`.

<TypesTree.useFilter hideDescription />

## createItems

Normalizes a custom item model into a collection for the `items` prop of `<Tree.Root>`, deriving each item's ID, label, and children.
Create static collections at module scope, and memoize dynamic collections by their data and every value their accessors read.
