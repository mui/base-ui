Base UI provides unstyled components for drag sources, drop targets, and previews. It supports mouse, touch, and pen input, with different [activation thresholds](/react/components/draggable#activation) for clicks and touch scrolling. Your application decides what a drop does, such as moving a card or rescheduling an event.

<DemoShapeSorter />

[Draggable](/react/components/draggable) makes an element a drag source, and [DropTarget](/react/components/drop-target) defines where it can be dropped. Add [DragAutoScroll](/react/components/drag-auto-scroll) to scroll containers as the pointer approaches their edges. The other guides cover [styling](/react/drag-and-drop/styling), [accessibility](/react/drag-and-drop/accessibility), and [testing](/react/drag-and-drop/testing).

## Concepts

A **kind** identifies a category of draggable items and its payload type. Declare it with `Draggable.createKind`, then pass it to a source's `kind` and a target's `accept`. Event handlers infer the type of `source.payload` from the kind:

```tsx title="Declaring a kind"
import { Draggable } from '@base-ui/react/draggable';
import { DropTarget } from '@base-ui/react/drop-target';

const card = Draggable.createKind<Card>('card');

<Draggable.Root kind={card} payload={cardData} />;

<DropTarget.Root accept={card} onDrop={({ source }) => move(source.payload.id)} />;
```

Each `createKind` call returns a value with a unique identity. Declare it once and share the returned value with every draggable and target in the interaction. Two separate `createKind('card')` calls do not match. The name is only a debugging aid.

If independently evaluated bundles cannot share the same value, use `Draggable.createGlobalKind<Card>('myapp/card')`. The same global key identifies the same kind across bundles and hot reloads. Prefix the key with your app or package name and use one payload type for that key. Incompatible types under the same key can match at runtime despite TypeScript's checks. Prefer `createKind` when you can share its returned value.

Every source and target on the page uses the same **drag manager**, with no provider required. The required `accept` prop prevents unrelated interactions from matching. Use `DropTarget.anyKind` to accept every drag. `Draggable.PreviewProvider` does not scope a drag. It provides the React tree where custom previews render.

Base UI tracks pointer input to implement **synthetic drag and drop**. These drags have no `dataTransfer` and stay within the page. To accept files dragged from the operating system, handle native drops by [passing native handlers through `render`](/react/components/drop-target#anatomy).

A drag can be over several nested drop targets at once. `location.current.dropTargets` lists them innermost first. Only the innermost receives `onDrop`; ancestors receive `onDragEnter`, `onDrag`, and `onDragLeave`. Returning `false` from `canDrop` skips that target. Returning `'reject'` blocks the drop at that position, including on descendants and ancestors.

To find the drop position within a target, use the target record's [`getLocalPoint()`](/react/components/drop-target#read-where-in-the-target-the-pointer-landed) method. It returns the pointer position inside the target as a fraction of its bounding box. Use it to resolve values such as a time in a day column or a position on a track without measuring the element in the handler.

Drag events carry a **location history**. Each location contains pointer input and the target stack at that moment:

- `location.initial` records where the drag began.
- `location.current` records the location for this event.
- `location.previous` records the location at the prior event. On the first event, it contains the pickup input and an empty target stack.

Compare `current` with `previous` to detect changes in pointer position or active targets.

## Setup

You do not need a provider for the default clone or `Draggable.ClonedPreview`. When you render custom content with `Draggable.Preview`, wrap that part of your app in a `Draggable.PreviewProvider`. Put it inside the context providers the preview needs:

```tsx title="Setting up drag and drop"
import { Draggable } from '@base-ui/react/draggable';

function App() {
  return (
    <ThemeProvider>
      <Draggable.PreviewProvider>
        <Board />
      </Draggable.PreviewProvider>
    </ThemeProvider>
  );
}
```

Custom preview content receives React context from above the nearest `Draggable.PreviewProvider`. Put a preview provider inside any local theme, direction, or store provider the preview needs. Changing the preview's DOM container does not change which React context it receives.

## Examples

### Draggable tabs

Reordering leaves the standard Tabs keyboard behavior in place. The arrow keys still move focus and select, <kbd>Alt</kbd>+<kbd>←</kbd>/<kbd>→</kbd> reorders the focused tab, and <kbd>Delete</kbd> closes it.

<DemoDraggableTabs />

### Calendar

A custom [modifier](/react/components/draggable#movement-modifiers) snaps the drag to the nearest day column and 15-minute slot, so the preview shows exactly where the event will land. Each column declares [`snap`](/react/components/drop-target#snap-to-steps), so the drop handler can read the snapped time without measuring the column.

<DemoSchedulerWeekView />

### Free dragging

Cards sit at absolute coordinates and drop anywhere. `restrictToElement` keeps pointer drags inside the canvas, while arrow keys move the focused card directly without starting a drag session.

<DemoFigmaBoard />

### Kanban board

[`useDragMonitor`](/react/utils/use-drag-monitor) resolves the closest column and insertion slot on every drag event, and an empty placeholder card marks where the drop will land.

<DemoKanbanBoard />

### File explorer

Drop a node on a folder, on the open grid, or on an ancestor in the breadcrumb to move it there. <kbd>Space</kbd> or <kbd>Enter</kbd> opens a focused folder. [`canDrop`](/react/components/drop-target#nested-drop-targets) refuses a folder dropped into its own subtree.
